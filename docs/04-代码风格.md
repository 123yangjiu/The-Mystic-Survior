# 04 · 代码风格

这个项目的代码是**一个人手写出来的**，所以风格不算"标准教科书"，但有一些很稳定的习惯。
新代码尽量照着来，改动的地方看起来才不会突兀。

> 下面每一条都来自仓库里真实存在的写法，不是凭空定的规范。

---

## 1. 文件与命名

| 对象 | 约定 | 例子 |
| --- | --- | --- |
| 脚本文件 | 小写下划线；与它挂载的场景同名 | `player_portal.gd` ↔ `portal.tscn` |
| 场景文件 | 同上；中文目录里的场景可以直接用中文名 | `确认物体.tscn` |
| 目录 | 中文为主（`大场景`、`文本及ui显示`），少量英文（`enemy`、`ability`） | — |
| `class_name` | 大驼峰 | `Player`、`EnemyComponent`、`ScreenFade` |
| 变量 / 函数 | 小写下划线 | `target_scene`、`_on_area_2d_body_entered` |
| 常量 | 全大写（较少用） | `SPAWN_R`、`SAVE_PATH` |
| 导出的可调参数 | 小写下划线，带中文注释 | `@export var breath_time:=1.6  # 一次呼吸的秒数` |
| 节点引用 | 用节点名的小写形式 | `$Area2D` → `@onready var area_2d:Area2D = $Area2D` |

**顺序**：绝大多数文件是 `extends` 在前、`class_name` 在后：

```gdscript
extends Node2D
class_name Game
```

---

## 2. 缩进与空格

- **缩进用 Tab**（GDScript 官方习惯，仓库里 108 个文件用 Tab，只有 8 个混了空格）。
- 函数签名里括号前**有空格**，返回类型两种写法都有，新代码建议统一成 `-> void`：

```gdscript
func _ready() -> void:
func _physics_process(_delta: float) -> void:
```

- 赋值尽量**不留空格**：

```gdscript
var direction:=Vector2(0,0)
GameEvent.paused=0
```

- 但函数调用参数、数组、字典里的逗号后面**留一个空格**：

```gdscript
var target_time = base_wait_time * exp(-decay * (difficulty - 1))
```

> 说明：项目里 `a+b` 和 `a + b` 都能见到。**同一段代码里保持一致**就行，
> 不要为了统一去改别人写的老代码。

## 3. 注释

注释是中文，而且写得比较"碎"—— 这是这个项目最值得保留的特点。

### 分区注释

大的功能块用横线分段：

```gdscript
#---- 启动游戏需要 ----

#---- 大厅 ↔ 一局游戏 ----

#---- 靠近：门醒来 ----
```

### 参数注释

每一个 `@export` 都在行尾写清楚单位或效果：

```gdscript
@export var breath_scale:=0.03      # 呼吸时缩放的最大偏移，0.03 = 放大 3%
@export var wake_time:=0.35         # 从“待机”到“醒来”的过渡时间
```

### 解释"为什么"而不是"是什么"

```gdscript
#挂到根节点上：切场景只会销毁 current_scene，不会销毁它
(Engine.get_main_loop() as SceneTree).root.add_child(fade)
```

### 类头部的文档注释

新写的脚本（`portal.gd`、`player_portal.gd`、`screen_fade.gd`）用了 `##` 写文件头，
Godot 会把它们显示在编辑器的帮助面板里，推荐继续用：

```gdscript
## 传送门“长什么样”的部分：待机呼吸、有人靠近时醒来、进入时收缩 + 爆发。
## 这里只管外观，谁可以进入、进入之后去哪里，交给子类（见 player_portal.gd）。
```

## 4. 类型标注

能标就标，尤其是 `@onready` 和函数返回值：

```gdscript
@onready var area_2d: Area2D = $Area2D
@export var upgrade_pool:Array[AbilityUpgrade]

func _on_check_body_entered(body:Node2D)->void:
```

几个坑（都真实踩过）：

- `var k := _pulse_t/max(x, 0.1)` 会报 **"Cannot infer the type"** —— `max()` 返回 Variant。
  改成 `var k:float = ...` 就行。
- `var node = get_node_or_null("X")` 赋值给 `Sprite2D` 类型的变量时，要加 `as`：
  `get_node_or_null("Glow") as Sprite2D`。
- 小对象能省则省：`.tscn` 里已经写了类型的属性不用在脚本里再 `match`。

## 5. 条件与匹配

否定条件几乎都用 `!`（老代码里偶尔能看到 `not`）：

```gdscript
if ! area is AreaInComponent:
	return
if ! is_player_entered or ! is_timer_ready:
	return
```

多分支用 `match`，少写 if-else 链：

```gdscript
match GameEvent.mode_index:
	0,1:
		wound_degree = 0.5
	_:
		wound_degree = 1.0
```

> 有个小细节：项目里 `else :`（冒号前带空格）和 `else:` 都存在，新代码用 `else:`。

---

## 6. 信号与解耦

- **跨模块一律走信号**，不要 `get_node("../管理器的某个方法")` 硬调。
- 信号发出前的"加工"写在 `GameEvent` 里，例如：
  `emit_increase_experience(n)` 会先乘上 `increase_percent` 再发。
- 不用的信号加 `@warning_ignore("unused_signal")`，保持编辑器干净。

```gdscript
@warning_ignore("unused_signal")
signal victory
```

## 7. 动画 / 特效的写法

项目里动画基本不用 AnimationPlayer，而是 **Tween + `_process` 手算**：

```gdscript
#一次性动作用 Tween
var tween = create_tween().set_parallel().set_ease(Tween.EASE_IN_OUT)
tween.tween_property(left, "modulate", Color(0,0,0,1), 0.4)

#循环动作（呼吸、旋转）用 _process 里的 sin()
var breath := sin(_time * TAU / breath_time)
```

这么写的原因：参数都在 `@export` 上，改手感不用打开动画编辑器。

粒子用 `GPUParticles2D + ParticleProcessMaterial`，
每张粒子图对应一个发射器（火星 / 浮尘 / 旋流），区别只在于 `ParticleProcessMaterial` 的参数。

## 8. 场景 ('.tscn') 的写法

- 节点名用中文没问题（`占位符`、`实体`、`前景`），但**脚本里引用它们时要小心**
  （`$占位符` 合法，只是不好搜索，建议给节点加 `@export` 或在 `@onready` 里写清楚）。
- 可调的节点属性放在`.tscn`里，逻辑放脚本里。
- 需要被外部设置的引用，用 `@export` 而不是 `@onready` + 路径硬编码
  （`target_scene`、`setting_screen`、`died_screen` 都是这么做的）。
- **二进制 `.scn`**（`main_map.scn`、`game.scn`）也在仓库里，它们是编辑器保存的大场景，
  提交前注意别把无意的改动一起带上。
