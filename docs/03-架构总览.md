# 03 · 架构总览

这一页讲的是"整个游戏是怎么串起来的"。看懂三件事就能改大部分代码：

1. `GameEvent`（自动加载的信号总线）负责**跨场景通信**；
2. 敌人是**组件拼装**出来的，不是继承出来的；
3. 能力、升级、刷怪都靠 `resource/` 里的 `.tres` **数据驱动**。

---

## 一、启动流程

```text
启动 Godot
  ├─ 加载 project.godot 里的 [autoload]
  │    ├─ GameEvent         (scene/大场景/game_event.tscn)   ← 信号总线 + 全局状态
  │    └─ AchievementManager(resource/achievement/...)       ← 成就读写
  ├─ 加载主场景 scene/大场景/main_map.scn
  │    └─ MainMap._ready() → GameEvent.end_run() + 放大厅音乐
  └─ 玩家走进传送门
       └─ PlayerPortal.enter_game()
            ├─ GameEvent.begin_run()          ← 初始化一局的状态
            └─ ScreenFade.change_scene(game.scn) → 淡出 → 切换 → 淡入
```

主场景在 `project.godot` → `[application] run/main_scene`。
（改造前这里指向 `scene/大场景/maintheme.tscn` 主界面，现在指向 `main_map.scn`。）

## 二、GameEvent：全局信号总线

`script/gamevent.gd` 挂在自动加载场景 `game_event.tscn` 上，游戏里任何地方都可以直接写
`GameEvent.xxx`，不需要 get_node，也不需要跨场景传参。

### 1. 它承担了两件事

| 职责 | 例子 |
| --- | --- |
| **发信号**（谁发生了什么） | `GameEvent.experience_bottle_collected.emit(x)` |
| **存全局状态**（这一局现在什么情况） | `GameEvent.difficulty`、`GameEvent.mode_index`、`GameEvent.play_global_position` |

### 2. 常用信号

| 信号 | 什么时候发 | 谁在听 |
| --- | --- | --- |
| `experience_bottle_collected(number)` | 吃到经验瓶 | `experiencemanager.gd` |
| `blood_bottle_collected(number)` | 吃到血瓶 | `player.gd` |
| `ability_upgrade_add(upgrade, current_upgrade)` | 选完一张升级卡 | 各个能力控制器、`player.gd`、`拾取范围.gd` |
| `more_difficulty(difficulty)` | 难度计时器到点，难度 +1 | `enemy_manager`、`enemy_producer`、`musicmanager` |
| `player_died` | 玩家死亡 | 结算相关 |
| `victory` | 倒计时结束 | `upgrademanager.gd` |
| `collision_disappear` / `collision_disappear_end` | "看不见的敌人"事件开始 / 结束 | `collision_component`、`effect_component` |
| `always_stop` / `always_start` | 暂停 / 恢复时，需要跟着停的东西 | `musicmanager` |
| `mode_change` | 切换难度模式 | `nandu_select.gd` |

### 3. 常用函数

| 函数 | 作用 |
| --- | --- |
| `begin_run()` | **开始一局**：重置难度 / 暂停 / 计时器 `is_start=true`（传送门调用） |
| `end_run()` | **回到大厅**：把上一局的暂停、难度、计时器清干净 |
| `start(is_start_always)` / `stop_game(is_stop_always)` | 暂停栈的入栈 / 出栈（`paused` 计数 >0 时 `get_tree().paused=true`） |
| `emit_more_difficulty()` | 难度 +1 并发信号 |
| `emit_increase_experience(n)` / `emit_increase_blood(n)` | 按 `increase_percent` 放大后再发信号（"药效增强"升级就改这个系数） |
| `refresh()` / `re_game()` | 重置全局数据 / 重开一局 |

> 💡 `paused` 是个**计数器**而不是布尔值：升级选卡、设置、暂停菜单都会让 `paused+1`，
> 只有减回 0 才真正 `get_tree().paused=false`。这是全项目最容易踩坑的地方之一。

## 三、敌人：组件化拼装

> 想动手加东西时，模板和现成工具函数都整理在 [12-模板与工具函数](12-模板与工具函数.md)，这一节只讲原理。

### 1. 基类 `EnemyComponent`

所有敌人组件都继承 `script/class/enemy_component.gd`：

```gdscript
class_name EnemyComponent
extends Node2D

func _ready() -> void:
	# 自动找到自己属于哪个 Enemy，并登记进去
	if ! owner is Enemy:
		owner = owner.get_parent() if owner else get_parent()
	if ! owner.is_node_ready():
		await owner.ready
	if owner is Enemy:
		owner.all_component.append(self)
	initial()          # 子类重写这个
```

好处：组件自己会"报户口"，`Enemy.all_component` 里就找得到所有同类，
不用在敌人脚本里 `get_node` 一个个连。

### 2. AreaInComponent：伤害区的胶水层

游戏里所有"会碰到人的范围"都套了一层 `Area2D + inside_collision.gd`（类名 `AreaInComponent`）：

```text
攻击区(AreaInComponent) ──进入──▶ 受伤区(AreaInComponent)
                                    │ return_component()
                                    ▼
                              找到它属于哪个 WoundComponent
```

这条链路让"谁打谁"变成一次组件查询，而不是靠节点路径硬连。
传送门判断"进来的是不是玩家"用的也是同一套方式。

### 3. 物理层约定

| 层 | 名字 | 谁在用 |
| --- | --- | --- |
| 1 | 地形 | 地图边界 |
| 2 | 玩家受伤区域 | 玩家的 `WoundComponent` |
| 3 | 敌人受伤区域 | 敌人的 `WoundComponent` |
| 4 | 敌人碰撞区域 | 挡路的敌人 |
| 5 | 玩家拾取区 | 玩家的 `拾取范围` |
| 6 | 玩家实体 | 玩家本体（**传送门就是检测这一层**） |
| 7 | 传送门 | 传送门自己的 Area2D |
| 9 | 蘑菇碰撞层 | 蘑菇怪的专属层 |

### 4. 一个敌人是怎么"长"出来的

```text
wolf.tscn (CharacterBody2D, 脚本 Enemy)
├── AnimatedSprite2D
├── health_component      → HealthComponent   (血量)
├── WoundComponent        → WoundComponent    (受伤)
├── velocity_component    → VelocityController(追击玩家)
├── AttackComponent       → AttackComponent   (碰到玩家扣血)
├── collision_controller  → CollisionComponent(实体碰撞)
├── drop_component        → DropComment       (死亡掉落)
└── EffectComponent       → EffectComponent   (特殊天气/事件表现)
```

想加新敌人：复制 `enemy_template.tscn` → 摆组件 → 在 `resource/enemy/` 加一条
`EnemyUnlockEntry`（填 ID、解锁难度、权重、血量）→ 丢进 `enemy_manager.tscn` 的
`all_enemy` 数组。

### 5. 敌人数据 `EnemyUnlockEntry`

`resource/enemy/enemy.gd`，字段：

| 字段 | 含义 |
| --- | --- |
| `scene` | 敌人场景 |
| `ID` | 枚举 `ALL_ID`（代码里按 ID 做特判，比如"逃跑箱子""巫婆"） |
| `unlock_difficulty` | 难度到达几级开始出现 |
| `disapear_difficulty` | 难度到几级后不再出现（默认 100 = 一直有） |
| `weight` | 随机权重 |
| `max_health` | 用来给 `EnemyManager` 估算场上总血量、动态调整刷怪速度 |

## 四、能力系统

```text
AbilityController            (定时释放的基类：冷却 / 伤害 / 数量 / 音量)
├── FlyAbilityController     (飞出去打人)
│   ├── sword_ability_controller   剑
│   ├── fireball_controller        火球
│   └── AK47AbilityController      枪械
│       ├── rpg / shotgun / sniper_rifle
└── 直接继承 AbilityController 的
    ├── light_ability_controller   圣光
    ├── ring_ability_controller    光环
    └── heaven_fruy_controller2    天堂之怒
```

- **飞行物**用 `FlyThing`（子弹、剑、火箭），**留在原地**的用 `AgainstThing`（光环、圣光）。
- 所有能力都监听 `GameEvent.ability_upgrade_add`，用 `match upgrade.ID` 决定自己怎么变强。
- 每个能力控制器都是挂在玩家 `abilitymanager` 节点下的一颗子节点，
  由 `AllGunAbilityController` 负责"换枪"（换掉整颗子节点）。

### 升级卡片数据 `AbilityUpgrade`

`resource/ability_upgrade.gd`，`resource/upgrades/**/*.tres` 是全部卡片。
关键字段：

| 字段 | 含义 |
| --- | --- |
| `ID` / `Sort` | 唯一 ID / 分类（剑、枪、光环……） |
| `is_init` / `is_unlock` | 是不是初始就有的 / 是不是"解锁新能力"型（选完会从池子里移除） |
| `lock_code` / `self_lock` | 互斥锁：一个能力的 `self_lock` 等于另一个的 `lock_code` 时，两者不能同时出现 |
| `Description` | 卡面文字 |

`upgrademanager.gd` 维护三个池子：`can_chose_pool`（主池）、`no_chose_pool`（暂时不可选）、
`mystrious_pool`（神秘池）。同一张卡**第二次被选中后**离开主池、进入神秘池，
之后只有 2% 概率再出现；神秘池本身也有次数上限（`limit_int`），到顶后彻底出池。

## 五、管理器

| 管理器 | 关键职责 |
| --- | --- |
| `EnemyManager` | 维护"已解锁敌人池"、按权重抽怪、按难度曲线缩短刷怪间隔、按场上总血量微调节奏 |
| `enemy_producer.gd` | 决定怪**刷在哪里**、什么时候放特殊事件（包围圈、箭头阵、Boss） |
| `upgrademanager` | 升级时抽 3 张卡并弹出选卡界面；维护能力数量与互斥 |
| `experiencemanager` | 经验条、等级、每级所需经验的成长曲线 |
| `gametimemanager` | 一局 600 秒（`is_long` 挑战下 900 秒），到点发 `victory` |
| `MusicManager` | 按难度分段播放音乐，暂停时 `stream_paused` |

## 六、分组的约定

代码里通过 `get_tree().get_first_node_in_group(...)` 找图层，所以**组名别乱改**：

| 组名 | 挂谁 | 用途 |
| --- | --- | --- |
| `前景图层` | `game.scn` 里的 `前景` | 能力、飘字都在这里生成，保证画在最上面 |
| `enemylayer` | `game.scn` 里的 `enemy` | 刷怪统一挂这里，方便遍历和清理 |
| `实体图层` | `game.scn` 里的 `实体` | 经验瓶 / 血瓶 |
| `player` | `player.tscn` 根节点 | 玩家 |
| `yaogan` | `虚拟摇杆` | 手机摇杆 |
| `enemy` / `高级` / `中级` | 单个敌人 | 敌人的趣味分组（成就、筛选用） |

## 七、一局游戏的完整数据流

```text
难度计时器(37s) ──▶ GameEvent.emit_more_difficulty()
                        │
                        ├─▶ EnemyManager  解锁新怪 / 缩短刷怪间隔
                        ├─▶ EnemyProducer 到特定难度放特殊事件
                        └─▶ MusicManager  换更激烈的曲子

玩家击杀 ──▶ DropComponent 掉经验瓶 ──▶ 拾取范围收集
                                          │
                                          ▼
                                 ExperienceManager 升级
                                          │
                                          ▼
                              UpgradeManager 抽 3 张卡 ──▶ 选卡界面
                                          │
                                          ▼
                           GameEvent.ability_upgrade_add(卡片, 已拥有)
                                          │
                    ┌─────────────────────┼────────────────────┐
                    ▼                     ▼                    ▼
             各能力控制器            玩家(盔甲/飞毛腿)      拾取范围(吸铁石)
```
